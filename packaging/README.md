# Packaging status

CI generates AppImage, `.tar.xz`, `.deb` and `.rpm` packages. Native prefix
installs are also available. Formats generated by CI are not proof of successful
installation/capture on every distribution; verify the exact release artifact
and its host dependencies.

## Package formats

- `Trophy-<version>-x86_64.AppImage`: portable application bundle; make it executable and keep its path stable for autostart.
- `Trophy-<version>.tar.xz`: native install-tree archive, not a self-contained AppImage; preserve its directory layout and provide compatible host libraries.
- `Trophy-<version>-amd64.deb`: native Debian-family package.
- `Trophy-<version>-x86_64.rpm`: native RPM-family package.

Native CI builds target **Ubuntu 26.04** (DEB/archive) and **Fedora 44** (RPM),
using each distribution's Qt/FFmpeg packages. They are not universal Debian/RPM
packages: older distributions and different Qt private ABIs can be incompatible.
The AppImage's SDK build, tests and packaging use **Ubuntu 24.04**, with Qt 6.12.0.
Its finished ELF payload is gated at GLIBC 2.39, GLIBCXX 3.4.32 and CXXABI 1.3.14;
this is not a claim that every older distro, GPU driver or desktop is supported.
The AppImage does not bundle a replacement glibc or vendor GPU drivers. Native
DEB/TXZ/RPM packages retain their distro-specific targets above. See
[container package checks](containers/README.md) for reproducible build/test commands.
Headless installation/startup does not establish optional encoder availability.
The AppImage also expects the normal host PipeWire client library/configuration
from a PipeWire-enabled Wayland desktop; linuxdeploy intentionally excludes that
library. Clean-baseline checks provide these ordinary desktop runtime libraries,
not Qt/FFmpeg/development packages or a running capture service.
In particular, Fedora's official FFmpeg-free build may omit libx264; software
H.264/share export needs a compatible codec-enabled FFmpeg provider according to
your distribution's guidance. These tests do not enable third-party repositories
or establish hardware capture/encoding on the target distribution.

Use the package matching your distribution/architecture and its normal package
manager for installation. CI normalizes these names and uploads AppImage,
Ubuntu DEB/TXZ and Fedora RPM artifacts independently as their checks complete.
A final verification job uploads `SHA256SUMS` covering all four formats without
duplicating the package uploads. Check which
assets were actually published on the release page; CI output does not itself
establish release publication or package smoke-test success. AUR and Flatpak
distribution are not maintained; do not recreate their removed packaging.

## Drafting a release

1. Set the next stable `X.Y.Z` in the root `VERSION` file on `dev`.
2. Open a pull request from `dev` into `main`. Review it and wait for CI to pass
   before merging. Configure branch protection to require these checks if merges
   must be technically blocked until green; workflow triggers alone do not enforce it.
3. Merge the PR through GitHub. The resulting push to `main` runs CI again.
4. After tests, both reporter jobs and all package/checksum checks pass, CI creates
   `vX.Y.Z` on the tested main commit and prepares a **draft** release with
   generated notes, the four packages and flattened `SHA256SUMS`.
5. Review the draft and click **Publish release** yourself. CI never publishes.

CI runs only for pull requests targeting `main` and pushes to `main`. Pushing to
`dev` or another branch without an open PR does not run CI; updates to a branch
with an open main PR rerun that PR's checks. Manual tag pushes do not run CI.
Main packages use `VERSION`; PR packages carry a PR number and commit suffix.

The tested commit must match the checkout and be reachable from `origin/main`.
Only main pushes can create tags or drafts. Versions at or below the highest
published stable release do not draft releases, so ordinary main updates without
a version bump do not create another release after that version is published.
Existing drafts and prereleases do not advance that stable-version baseline;
an unparseable published stable tag fails closed rather than guessing. With no
published releases, the first valid stable tag is eligible.

Existing tags are never moved. A retry for the same tested commit reuses its tag;
if that version's tag already points at another commit, choose a new version in
`VERSION` rather than silently retagging it. CI-created tags are lightweight;
no private signing key is installed in CI.

CI package and checksum artifacts expire after **14 days**; diagnostic artifacts
after **7 days**, and the internal SDK build handoff after **1 day**. Assets copied
to a GitHub draft/release are release attachments, not expiring Actions artifacts.

Retries preserve existing draft titles/notes and matching assets, upload missing
assets and refresh changed package/checksum assets while the release is still a
draft. Checksums upload last; interrupted uploads leave an unpublished draft for
the next successful run to repair. Already published
releases are not intentionally modified. Wait for the draft job to finish before
reviewing the assets/notes and clicking **Publish release** yourself. CI has no
automatic publication step. No extra combined package ZIP is created.

## Verification

Check a trusted finished AppImage (or deployed AppDir) against the baseline:

```sh
python3 packaging/check_appimage_abi.py Trophy.AppImage --report appimage-abi.json
```

This inspects required version nodes in every ELF, including nested plugins and
the AppImage runtime, not exported versions or just the main executable. It fails
closed on inspection errors, unsupported system ABI requirements or versions over
the limits. Symbol-version checks complement clean-baseline startup tests; they
do not prove every kernel/API/driver interaction works. Extraction executes the
trusted AppImage runtime. CI runs this gate before smoke tests and artifact upload.
SDK compiler/GTest caches use baseline-specific keys to avoid importing compiled
objects from newer runners.

### Portable friend testing (experimental)

See [FRIEND-TESTING.md](FRIEND-TESTING.md) for the consent-based AppImage preview,
bundled source-free unit/native GPU tests, result collector and developer-side
AppImage builder. Friends do not need Docker, namespaces, development dependencies
or a full install. Live detection setup remains explicit and may leave small
compositor/reporter integrations to clean up. GPU skips are incomplete coverage.
Validate the exact complete kit before distribution; source fixtures alone do
not establish portable runtime or hardware compatibility.

An installed tree needs the executable, `libTrophy.so`, both reporter
libraries, desktop/icon metadata, and the KWin script. Check `readelf -d`
for the executable's prefix-relative RUNPATH and `ldd` with
`LD_LIBRARY_PATH` unset. Native/AppImage AppStream metadata must launch
`trophy.desktop`.

Check a trusted extracted native prefix/DESTDIR tree or a CPack tar.xz with:

```sh
python3 packaging/smoke_native.py /path/to/Trophy.tar.xz --log /tmp/trophy-native-smoke.log
python3 packaging/smoke_native.py /path/to/extracted-root --log /tmp/trophy-prefix-smoke.log
```

The native checker requires `readelf`, `ldd`, `dbus-run-session` and compatible
host libraries. Archive extraction requires Python's `tarfile.data_filter`
(Python 3.12+ or a backport). It checks required application/library/reporter,
icon/license/helper and metadata files, binary execute/library read permissions, the AppStream
desktop association, prefix-relative RUNPATH and prefix-local `libTrophy.so`
resolution with loader overrides cleared. It then uses the isolated startup/QML/
graceful-shutdown harness below. Tar archives extract under a temporary spaced
path with traversal/link/device rejection and an extraction budget. This runs
package code and `ldd`: **only check trusted build artifacts**, not arbitrary
downloads. Extraction filtering is not a sandbox for executing untrusted code.

CI applies these checks to distro-native tar.xz and extracted DEB/RPM payloads.
It also installs, reinstalls, upgrades to a test-only later version, checks
startup, and removes each native package in a fresh matching runtime container.
Those runtime images contain inspection tools but no preinstalled Qt development
stack: declared dependencies must provide the QML modules and platform/image
plugins too. Optional/recommended dependencies are disabled during installation.
This validates the tested distributions/artifacts, not other distributions,
live desktop rendering/capture, or successful remote CI execution by itself.
The package-manager harness refuses to operate outside an explicitly marked
disposable container; never mount host system/config/runtime directories into it.
The Vulkan manifest is an enrollment template; explicit enrollment rewrites
its library path, so a build-tree path in that template is not a smoke failure.

Run a non-capture AppImage smoke test with:

```sh
python3 packaging/smoke_appimage.py /path/to/Trophy.AppImage --log /tmp/trophy-smoke.log
```

The harness uses temporary HOME/XDG directories, a private D-Bus with service
activation disabled, offscreen/software rendering, and disabled optional
integrations. It checks GUI initialization, QML errors, bundled platform/media
plugins and reporters, and graceful shutdown. It does **not** verify real
Wayland rendering, portal capture, hardware encoding or host autostart.

AppImages use `packaging/AppRun` to execute the actual `usr/bin/trophy` binary
with bundle-first library lookup; do not replace it with a root-level binary
symlink. Include Wayland platform, shell and graphics-integration plugins
explicitly: an offscreen launch alone cannot establish their presence.

When opted in, portable-bundle reporter libraries are copied atomically to
content-addressed files in `$XDG_DATA_HOME/trophy/reporters` (normally
`~/.local/share/trophy/reporters`). Enrollment must never reference a temporary
AppImage mount. Old helper versions remain available for already-running games.
Previously enrolled GL configurations refresh on startup; session activation
still follows the existing next-login behavior. Disabled modules are not
installed by lookup/status checks. Host/Steam-runtime ABI compatibility and
32-bit reporter support are not established by the smoke test.

## Static reporter ABI checks

### Reporter scope and anti-cheat caution

Neither reporter is certified compatible with anti-cheat systems. No hooking
change, allowlist or disabled-reporting flag can guarantee that a loaded
library will be accepted. Keep optional reporters off for protected games
unless the game's policy explicitly permits them. Trophy does not inspect,
hide from, or bypass anti-cheat software.

The current OpenGL toggle writes **session-wide** `LD_PRELOAD` configuration:
it loads the shim into unrelated dynamically linked programs, not just games.
Turning it off affects future login environments; already-running launchers
and their children can retain the old preload. Log out and back in after
disabling. `DISABLE_TROPHY_DETECTION=1` stops shim reporting, but cannot prevent
the dynamic loader from loading a library named in `LD_PRELOAD`.

Prefer leaving global enrollment off and, for a known-compatible native game,
scoping preload to its launch command (example for the native `~/.local`
64-bit install):

```sh
env LD_PRELOAD="$HOME/.local/lib/trophy/libtrophy_gl_shim.so${LD_PRELOAD:+:$LD_PRELOAD}" /absolute/path/to/game
```

This also affects that game's child processes. It is not an anti-cheat safety
guarantee or a validated Steam/Proton/32-bit recipe. AppImage mount paths must
not be used as persistent launch settings. A future per-game enrollment UI
should replace the broad session toggle, with explicit migration/consent,
durable paths, loader-path validation and architecture/runtime checks.

Shim coverage deliberately remains limited to exported GLX/EGL/SDL swap
functions. Games resolving entry points privately may bypass it; do not add
`dlsym`/get-proc-address interception simply to increase coverage without a
separate compatibility review. Remaining reporter verification includes real
loader/driver execution, Vulkan fork/unload and allocation/thread-failure paths,
and host/Steam ABI tests. Fake native-operation tests do not establish these.

Run without loading the reporters or starting a game:

```sh
python3 packaging/check_reporter_abi.py /path/libtrophy_layer.so /path/libtrophy_gl_shim.so
python3 packaging/check_reporter_abi.py --sysroot /path/materialized-sysroot /path/libtrophy_layer.so
PYTHONDONTWRITEBYTECODE=1 python3 tests/test_ReporterAbi.py
```

The Linux checker uses `readelf` and host `ldconfig -p` (or libraries inside
the supplied sysroot). It checks ELF class/machine, dependency closure,
required version definitions and strong versioned symbol exports. Inspection
is bounded; absent/ambiguous providers fail rather than silently selecting
another architecture. A sysroot never falls back to host providers. Exit codes
are 0 for a static pass, 1 for detected mismatches and 2 for an inconclusive
inspection/tool error. Reports are JSON; redirect generated evidence under
`/tmp/opencode`. This does not simulate RPATH/RUNPATH, environment overrides,
unversioned/weak symbol resolution, driver loading or loader interposition.

The 2026-10-13 local x86_64 helpers passed against materialized host providers.
Both require `GLIBC_2.34`; the Vulkan helper also requires
`GLIBCXX_3.4.32`. Installed Sniper `3.0.20260805.254768` mtree metadata lists
`libc-2.31.so` and `libstdc++.so.6.0.28`: an **older-base ABI advisory**, not
a verified Steam/Proton failure. Its content-addressed `files/` tree is not
a materialized sysroot, and pressure-vessel can select override providers.
Metadata names alone do not prove exported symbols or actual provider
selection. Native host results do not establish Steam-runtime compatibility.

Isolated trivial C and C++ `-m32` compile/link probes succeeded locally; no
probe binary was run. The current helpers are ELF64/x86_64 and cannot serve
32-bit processes. Those probes do not establish 32-bit Vulkan dependencies,
reporter builds, enrollment or game compatibility. No live game, host install,
SDK installation or compiler/linker ABI workaround was used for these checks.
