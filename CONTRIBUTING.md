# Contributing to Trophy

Thank you for your interest in contributing to Trophy! Community contributions are welcome, whether they involve bug fixes, new features, translations, documentation or general improvements.

## Reporting Bugs

Before submitting a bug report, please check whether the issue has already been reported.

When reporting a bug, please include:

- Trophy version.
- Linux distribution and version.
- Desktop environment and compositor.
- Relevant hardware or software information.
- Steps to reproduce the issue.
- Expected and actual behaviour.
- Relevant logs or screenshots, where applicable.

Please remove any sensitive or personal information from logs before submitting them.

## Suggesting Features

Feature suggestions are welcome. Please open a GitHub issue describing:

- The proposed feature.
- The problem it addresses.
- How it would benefit Trophy and its users.

For substantial features or architectural changes, please discuss your proposal with the maintainers before beginning implementation.

## Development Principles

Contributions should respect Trophy's core development principles:

- **Wayland-first:** Trophy is designed for Linux systems running Wayland.
- **Compositor independence:** Avoid unnecessary dependencies on specific desktop environments or compositors.
- **Compatibility:** Avoid approaches that unnecessarily interfere with games, anti-cheat systems or other applications.
- **Performance:** Minimise unnecessary resource consumption and background processing.
- **Privacy:** Respect user privacy and avoid unnecessary collection or transmission of user data.
- **Maintainability:** Prefer straightforward, documented and maintainable implementations over unnecessary complexity.
- **Consistency:** Follow Trophy's existing architecture, coding conventions and visual design.

New dependencies should be justified and compatible with Trophy's licence.

## Submitting Contributions

1. Fork the Trophy repository.
2. Create a branch for your changes.
3. Implement and test your changes.
4. Commit your changes with clear and descriptive commit messages.
5. Submit a pull request to the official Trophy repository.

Please keep contributions focused on a specific feature, improvement or bug fix. Avoid including unrelated changes in the same pull request.

## Pull Request Requirements

Before submitting a pull request, please ensure that:

- Your changes build successfully.
- Your changes have been appropriately tested.
- Existing functionality has not been unintentionally affected.
- Your code follows the project's existing conventions.
- Relevant documentation has been updated where necessary.
- No unnecessary dependencies, generated files or sensitive information have been included.
- Any third-party code or assets are appropriately attributed and licensed.

Pull requests should clearly explain what has changed, why the change is necessary and how it has been tested.

Screenshots or recordings are encouraged for changes affecting the user interface.

## AI-Assisted Contributions

The use of AI-assisted development tools is permitted.

However, contributors are responsible for understanding, reviewing and testing all submitted code, regardless of how it was produced.

AI-generated contributions must meet the same quality, security, licensing and maintainability standards as any other contribution.

## Security Vulnerabilities

Please do not publicly disclose security vulnerabilities through ordinary GitHub issues.

Where available, use GitHub's private vulnerability reporting feature or contact the maintainers privately through an official project contact channel.

## Forks and Branding

Development forks and community contributions are encouraged.

Independently distributed modified versions of Trophy must respect the project's [Trademark and Attribution Policy](TRADEMARK.md).

Development forks intended for contribution to Trophy do not need to adopt separate branding.

## Review Process

All contributions are subject to review by the project maintainers.

Maintainers may request changes or decline contributions that do not align with the project's technical requirements, design direction, security standards or overall objectives.

Submitting a contribution does not guarantee its acceptance.

## Community Conduct

Please treat other contributors, maintainers and users with respect.

Constructive criticism and technical disagreements are welcome. Harassment, discrimination, personal attacks and deliberately disruptive behaviour are not acceptable.

Thank you for helping improve Trophy!
